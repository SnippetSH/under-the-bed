# 그림 자리 안내 (M6b) — 디렉터 모델링 가이드

포기·구조물·장치는 **3D 모델**, 캐릭터만 **서 있는 평면 그림**이에요.
아래 이름으로 파일을 넣으면 **코드 수정 없이** 그 모델이 쓰여요. 파일이 없으면 코드로 만든 자리 채움 모델(임시 모양)이 나와요.
불러오는 코드는 `game/scripts/art_library.gd`, 자리 채움 모델은 `game/scripts/placeholder_meshes.gd`예요.

## 1. 공통 규약

| 항목 | 규약 |
| --- | --- |
| 단위 | **1 단위 = 1 m** |
| 축 | **Y 위**. 앞면은 **+Z** 쪽 (카메라가 하우스 안쪽 끝에서 출입구를 바라봐요. +Z가 카메라 쪽) |
| 원점 | **땅에 닿는 바닥면의 가운데** (포기·열매·꽃은 베드 윗면에 닿는 점) |
| 파일 형식 | **`.glb`(glTF 2.0 바이너리) 먼저**, 없으면 **`.obj` + `.mtl`**. 같은 자리에 둘 다 있으면 `.glb`를 써요 |
| 텍스처 | 모델 파일과 **같은 폴더**(`game/art/models/`)에. `.obj`는 `.mtl`의 `map_Kd`(파일 이름만), `.glb`는 파일 안에 넣어도 돼요 |
| 재질 | `.mtl`에서 읽는 것: `Kd`(바탕색), `d`/`Tr`(투명도), `map_Kd`(바탕 텍스처). `.glb`는 glTF 재질 그대로 |
| 노드 | `.glb` 안의 여러 메시·노드 변환은 한 모델로 합쳐요. 뼈대(스킨)·애니메이션은 쓰지 않아요 |
| 적용 | 게임을 다시 시작하면 바뀐 파일을 읽어요 (실행 중 바꾸면 다음 실행부터) |

- 편집기(Godot)가 `.glb`/`.obj`를 가져오기(import)하면서 `.import` 파일을 만들 수 있어요. 게임은 원본 파일을 직접 읽어요. `.import`는 커밋하지 않아요(.gitignore).
- 포기 모양 변화(포기마다 조금씩 돌리고 크기 바꾸기)는 코드가 해요. 모델은 한 가지 모양이면 돼요.

## 2. 자리 목록 (`game/art/models/<이름>.glb` 또는 `.obj`)

### 포기: 딸기 생육 단계 모델 (디렉터 모델, 2026-11-20) — 지금 쓰는 것

`strawberry_s*.obj` + 함께 쓰는 `strawberry_stages.mtl`(재질은 `usemtl` 이름별 `Kd` 색, 텍스처 없음). 꽃·열매·런너가 **모델 안에** 있어서 아래 덧붙임(`flower`·`fruit_*`)을 얹지 않아요. 단계마다 MultiMesh 하나(용량 640)로 그려요.

| 파일 이름 | 무엇 | 삼각형 | 언제 (포기마다, 보이는 것 `get_tile_visuals`만) |
| --- | --- | --- | --- |
| `strawberry_s1_transplant` | 잎 3장 | 834 | 아래 어느 것도 아니고 잎 크기 단계 1(`leaf_g_per_m2` < `leaf_stage_thresholds_g_per_m2[0]`). 정식 미리 보기도 이것 |
| `strawberry_s2_vegetative` | 잎 5장 | 1,346 | 아래 어느 것도 아니고 잎 크기 단계 2 이상 |
| `strawberry_s3_flowering` | 잎 7, 꽃 5 + 봉오리 2 | 2,650 | 이 포기 몫에 꽃·꽃봉오리(`open_flower_count`)가 있음 |
| `strawberry_s4_fruit_set` | 풋열매 5 + 꽃 4 + 봉오리 1 | 3,154 | 이 포기 몫에 열매(`fruit_count`)가 있음 |
| `strawberry_s5_harvest` | 완숙 3 + 착색 1 + 풋열매 3 + 꽃 2 + 봉오리 1 | 2,862 | 이 포기 몫에 익어 가는 열매(`ripening_fruit_count`)가 있음 |
| `strawberry_s6_runners` | 런너 + 익은 열매 | 3,358 | 런너 모습으로 바뀐 포기(아래)이고 이 포기 몫에 열매가 있음 |
| `strawberry_s6_runners_no_berrys` | 잎 15, 런너 4줄 (열매 없음, 파일 이름은 디렉터 표기 그대로) | 3,418 | 런너 모습으로 바뀐 포기이고 열매 몫이 없음(꽃만 있어도 이것) |
| `strawberry_s7_dead` | 고사 | 1,842 | 칸의 포기가 죽음(`crop_present` 이고 `crop_alive` 아님). 가장 먼저 봐요 |

- **포기 몫**: 칸 하나의 개수를 그 칸 포기 8개에 앞 포기부터 고르게 나눠요(예전 덧붙임과 같은 규칙, `plant_art.share`). 그래서 꽃 2개인 칸은 꽃 핀 포기 2개, 익어 가는 열매 3·열매 5·꽃 10인 칸은 s5 3포기·s4 2포기·s3 3포기예요. 꽃·열매 모습의 포기 수가 칸의 실제 개수를 넘지 않아요. 우선순위: s7 > 런너 > s5 > s4 > s3 > s1/s2.
- 실제 작기에서는 열매 수가 금방 꽃보다 많아져서 **s3은 아주 잠깐**(표준 작기 48~60일에 수십 포기)만 보이고 곧 s4·s5가 돼요. 비료 없이 키운 밭(`char_planted`)은 잎이 크기 단계 1을 넘지 않아서 꽃·열매 몫이 없는 포기는 작기 내내 s1이에요.
- **런너 모습 (꾸밈만, 디렉터 2026-11-20)**: 시뮬레이션에는 런너가 없어요(딸기 생육 명세 "런너는 없어요"). 화면만 늦봄에 런너가 덮인 모습을 보여 줘요: `[plant_models] runner_start_month`·`runner_start_day`(4월 25일)부터 `runner_step_days`(1.5일)마다 아직 안 바뀐 살아 있는 포기의 `runner_fraction_per_step`(3.5%)가 바뀌고, 살아 있는 동안 그대로예요(죽으면 s7). 포기마다 고정 해시(칸 번호, 칸 안 번호, 고정 소금)로 바뀌는 단계를 정해서 저장할 것이 없고, 매 프레임·저장 후 불러오기·빨리 돌리기 속도와 무관하게 같아요. 날짜는 게임 달력(`get_time()`의 `day_of_year`, `elapsed_days`)만 봐요: 이번 작기 안에서 시작일을 처음 지난 날부터 세고(작기가 4월 25일 뒤에 시작하면 다음 해 4월 25일까지 기다려요), 시작일 당일이 1단계예요. N단계 뒤 바뀐 몫의 기댓값은 1 − (1 − 0.035)^N (5월 15일 = 14단계 ≈ 39%). 코어·명령·기록·해시·칸 정보에는 영향이 없어요. 런너로 바뀐 포기는 몫에 꽃·열매가 있어도 런너 모델이 이겨요(열매 몫이 있으면 열매 달린 런너, 없으면 열매 없는 런너).
- **크기**: 모델은 m 단위(다 자란 s5가 지름 약 0.6 m, 높이 약 0.3 m)라서 `[plant_models] stage_model_scale`(0.6, 게임용 임의값)을 곱해요. 0.4·0.5·0.6을 1920×1080에서 캐릭터(1.15 m) 옆에 놓고 비교해서 정했어요(0.6: s5 지름 약 0.37 m, 포기가 하나하나 보이고 베드 흙이 사이로 보여요). 포기마다 꾸밈 회전·크기(`yaw_jitter_deg`, `scale_jitter`)는 그대로예요.
- **땅 아래로 내려간 부분**: s5의 늘어진 열매(y −0.031 m), 런너 모델의 런너(y −0.095 m)는 원점(베드 윗면)보다 아래예요. 배율 0.6이면 각각 약 2 cm, 6 cm예요. 열매 끝은 베드 흙에 살짝 묻혀 보이고(평면이 겹치지 않아 깜빡임 없음), 베드 가장자리 포기의 런너는 통로 쪽으로 늘어져요.
- **파일이 없으면**: s1~s5·s7 중 하나라도 없으면 아래 예전 자리(크기 4단계 + 덧붙임, 그것도 없으면 코드 자리 채움)로 그려요. 런너 둘은 선택이라 하나만 있으면 그것을 같이 쓰고, 둘 다 없으면 런너 모습 없이 s1~s5로 그려요.
- 해석기(`art_library._load_obj`)가 읽는 것: `o` 여러 개, `usemtl` 여러 묶음(같은 재질 이름은 한 표면으로 합쳐요), 함께 쓰는 `mtllib`, 법선만 있고 UV 없는 면(`f a//n`), 다각형(부채꼴로 나눔). 검사 `engine_C13_model_slots` D1이 8개 파일의 삼각형 수·표면 수·재질 색·법선을 확인해요.

- **한 칸(1 m × 1 m)에 포기 8개**(2줄 × 4)가 들어가요. 포기 사이 간격은 옆으로 약 0.46 m, 앞뒤로 약 0.25 m예요. 다 자란 포기는 앞뒤 이웃과 조금 겹쳐도 괜찮아요.
- 꽃·열매는 단계마다 정해 둔 자리에 코드가 붙여요. 자리는 `game/config/game_config.cfg`의 `[plant_models]`(`flower_offsets_stage1`~`4`, `fruit_green_offsets_stage*`, `fruit_red_offsets_stage*`, 포기 원점 기준 m, 게임용 임의값)에서 바꿔요. 열매는 `fruit_tilt_deg`만큼 눕혀서 놓아요.
- 그래서 단계 × 꽃 × 열매 조합을 다 만들 필요 없이 **포기 4단계 + 시든 포기 + 덧붙임 3개**면 돼요.

### 캐릭터 3D 모델 (선택): `game/art/models/character.glb`

있으면 평면 그림 대신 이 모델을 써요(`character_rig.gd`). 없으면 아래 평면 그림 자리를 써요.

| 항목 | 요구 |
| --- | --- |
| 형식 | **`.glb`만** (뼈대·애니메이션이 필요해서요. `.obj`는 뼈대·애니메이션을 담지 못해요) |
| 단위·축 | 1 단위 = 1 m, Y 위, **발바닥 = 원점**(두 발 사이 땅) |
| 앞면 | **+Z**. 게임이 캐릭터가 보는 방향(8방향)으로 Y축을 돌려요 |
| 키 | 약 **1.15 m** (`plant_art.character_height_m`과 맞춰 주세요. 게임이 크기를 바꾸지 않아요) |
| 애니메이션 이름 | `idle`(서 있기), `walk`(걷기), `run`(달리기, 선택), `work`(손으로 일하기, 선택) |
| 걷기·달리기 | **제자리 걸음**(뿌리 이동 없이, root motion 없음). 위치는 게임이 옮겨요 |
| 반복 | `idle`·`walk`·`run`은 처음과 끝이 이어지게(게임이 반복 재생으로 켜요) |
| 없는 클립 | `run` 없음 → `walk`를 달리기 배수(`run_speed_factor`, 지금 1.75)만큼 빠르게, `work` 없음 → `idle`, `idle` 없음 → 멈춘 자세 |
| 재생 시점 | 걸으면 `walk`, Shift를 누르고 걸으면 `run`, 행동 키를 누르고 서 있으면 `work`, 그 밖에는 `idle` |

- 확인한 것: 스크립트로 만든 시험 `.glb`(뼈대 없는 노드 애니메이션 `walk`만 / 2뼈 뼈대 + 스킨 + `idle`·`walk`·`work`)를 읽어 방향 돌리기, 클립 고르기·대신하기, 뼈 자세가 바뀌는 것까지(`tests/c13_model_slots.gd`, ctest `engine_C13_model_slots`). 같은 검사가 저장소의 `character.glb`(디렉터 모델)도 읽어 봐요: 지금 파일의 클립은 `idle`·`walk`·`run`이고 `work`가 없어서 행동 키를 누르고 있을 때는 `idle`이 나와요.
