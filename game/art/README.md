# 그림 자리 안내 (M6b) — 디렉터 모델링 가이드

포기·구조물·장치는 **3D 모델**, 캐릭터만 **서 있는 평면 그림**이에요.
아래 이름으로 파일을 넣으면 **코드 수정 없이** 그 모델이 쓰여요. 파일이 없으면 코드로 만든 자리 채움 모델(임시 모양)이 나와요.
불러오는 코드는 `game/scripts/art_library.gd`, 자리 채움 모델은 `game/scripts/placeholder_meshes.gd`예요.

## 1. 공통 규약

| 항목 | 규약 |
| --- | --- |
| 단위 | **1 단위 = 1 m** |
| 축 | **Y 위**. 앞면은 **+Z** 쪽 (카메라가 하우스 안쪽 끝에서 출입구를 바라봐요. +Z가 카메라 쪽) |
| 원점 | **땅에 닿는 바닥면의 가운데** (포기·열매·꽃은 베드 윗면에 닿는 점) |
| 파일 형식 | **`.glb`(glTF 2.0 바이너리) 먼저**, 없으면 **`.obj` + `.mtl`**. 같은 자리에 둘 다 있으면 `.glb`를 써요 |
| 텍스처 | 모델 파일과 **같은 폴더**(`game/art/models/`)에. `.obj`는 `.mtl`의 `map_Kd`(파일 이름만), `.glb`는 파일 안에 넣어도 돼요 |
| 재질 | `.mtl`에서 읽는 것: `Kd`(바탕색), `d`/`Tr`(투명도), `map_Kd`(바탕 텍스처). `.glb`는 glTF 재질 그대로 |
| 노드 | `.glb` 안의 여러 메시·노드 변환은 한 모델로 합쳐요. 뼈대(스킨)·애니메이션은 쓰지 않아요 |
| 적용 | 게임을 다시 시작하면 바뀐 파일을 읽어요 (실행 중 바꾸면 다음 실행부터) |

- 편집기(Godot)가 `.glb`/`.obj`를 가져오기(import)하면서 `.import` 파일을 만들 수 있어요. 게임은 원본 파일을 직접 읽어요. `.import`는 커밋하지 않아요(.gitignore).
- 포기 모양 변화(포기마다 조금씩 돌리고 크기 바꾸기)는 코드가 해요. 모델은 한 가지 모양이면 돼요.

## 2. 자리 목록 (`game/art/models/<이름>.glb` 또는 `.obj`)

### 포기 (MultiMesh로 640개를 한꺼번에 그려요)

| 파일 이름 | 무엇 | 크기 가이드 |
| --- | --- | --- |
| `plant_stage1` | 크기 단계 1 (어린 포기) | 지름 약 0.10 m |
| `plant_stage2` | 크기 단계 2 | 지름 약 0.17 m |
| `plant_stage3` | 크기 단계 3 | 지름 약 0.24 m |
| `plant_stage4` | 크기 단계 4 (다 자란 포기) | 지름 약 0.30 m, 높이 약 0.25 m |
| `plant_dead` | 죽은(시든) 포기 | 단계 3 정도 크기 |
| `flower` | 꽃 한 송이 (덧붙임) | 지름 약 4 cm. 원점 = 꽃 가운데, 꽃자루는 아래(-Y)로 |
| `fruit_green` | 덜 익은 열매 (덧붙임) | 길이 약 5 cm (실제보다 조금 크게, 화면에서 보이게). 원점 = 열매 끝, 꼭지는 +Y |
| `fruit_red` | 익어 가는 열매 (덧붙임) | `fruit_green`과 같은 크기·방향 |

- **한 칸(1 m × 1 m)에 포기 8개**(2줄 × 4)가 들어가요. 포기 사이 간격은 옆으로 약 0.46 m, 앞뒤로 약 0.25 m예요. 다 자란 포기는 앞뒤 이웃과 조금 겹쳐도 괜찮아요.
- 꽃·열매는 단계마다 정해 둔 자리에 코드가 붙여요. 자리는 `game/config/game_config.cfg`의 `[plant_models]`(`flower_offsets_stage1`~`4`, `fruit_green_offsets_stage*`, `fruit_red_offsets_stage*`, 포기 원점 기준 m, 게임용 임의값)에서 바꿔요. 열매는 `fruit_tilt_deg`만큼 눕혀서 놓아요.
- 그래서 단계 × 꽃 × 열매 조합을 다 만들 필요 없이 **포기 4단계 + 시든 포기 + 덧붙임 3개**면 돼요.

### 구조물

| 파일 이름 | 무엇 | 크기 가이드 |
| --- | --- | --- |
| `bed` | 베드 한 구간 | **정확히 1 m × 1 m 바닥**, 높이 0.15 m(윗면 y = 0.15, `layout.bed_height_m`). 한 칸에 하나씩 이어 붙여요 |
| `mulch_clear` / `mulch_black` / `mulch_white` | 멀칭 필름 한 칸 (투명 / 흑색 / 백색) | 1 m × 1 m, **원점 = 베드 윗면 가운데**(y 0이 베드 윗면). 아주 얇게 |
| `house_frame` | 비닐하우스 **뼈대** 1 m 구간 (아치 관 등, **비닐은 넣지 않아요**) | 폭 **6.7 m** 기준(x −3.35 ~ +3.35), 길이 방향(z) 1 m. 원점 = 구간 바닥 가운데. 길이 방향으로 반복하고, 폭이 다른 판에서는 x만 늘려요 |
| `aisle_floor` | 통로 바닥 타일 (선택) | 1 m × 1 m, 바닥 전체에 깔아요. 없으면 흙길 무늬 평면 |

- **피복 비닐과 측창은 코드가 상태대로 그려요**(`house_cover.gd`, 자리 없음): 지금 피복 겹수(`cover_layers`)만큼 비닐 겹을 안쪽으로 조금씩 겹쳐 그리고(바깥 겹 = 0, 겹마다 색을 조금 다르게), 겹마다 좌(0행 쪽 벽)·우 측창 비닐이 열린 정도(0 / 0.3 / 0.5 / 0.7 / 1.0)만큼 말려 올라가요(0.6초 애니메이션). 아치 윗부분은 카메라 시야를 위해 비워 둬요. 조정 값은 `game_config.cfg`의 `[cover]`.
- 카메라는 높이 약 3.1 m, 캐릭터 뒤 4.3 m에서 내려다봐요. 아치 꼭대기(약 4.3 m)가 카메라보다 높아요. 뼈대 모델이 시야를 많이 가리면 윗부분을 가늘게 해 주세요.
- 출입구 쪽 박공 비닐도 코드가 그려요(자리 없음).

### 캐릭터 3D 모델 (선택): `game/art/models/character.glb`

있으면 평면 그림 대신 이 모델을 써요(`character_rig.gd`). 없으면 아래 평면 그림 자리를 써요.

| 항목 | 요구 |
| --- | --- |
| 형식 | **`.glb`만** (뼈대·애니메이션이 필요해서요. `.obj`는 뼈대·애니메이션을 담지 못해요) |
| 단위·축 | 1 단위 = 1 m, Y 위, **발바닥 = 원점**(두 발 사이 땅) |
| 앞면 | **+Z**. 게임이 캐릭터가 보는 방향(8방향)으로 Y축을 돌려요 |
| 키 | 약 **1.15 m** (`plant_art.character_height_m`과 맞춰 주세요. 게임이 크기를 바꾸지 않아요) |
| 애니메이션 이름 | `idle`(서 있기), `walk`(걷기), `run`(달리기, 선택), `work`(손으로 일하기, 선택) |
| 걷기·달리기 | **제자리 걸음**(뿌리 이동 없이, root motion 없음). 위치는 게임이 옮겨요 |
| 반복 | `idle`·`walk`·`run`은 처음과 끝이 이어지게(게임이 반복 재생으로 켜요) |
| 없는 클립 | `run` 없음 → `walk`를 달리기 배수(`run_speed_factor`, 지금 1.75)만큼 빠르게, `work` 없음 → `idle`, `idle` 없음 → 멈춘 자세 |
| 재생 시점 | 걸으면 `walk`, Shift를 누르고 걸으면 `run`, 행동 키를 누르고 서 있으면 `work`, 그 밖에는 `idle` |

- 확인한 것: 스크립트로 만든 시험 `.glb`(뼈대 없는 노드 애니메이션 `walk`만 / 2뼈 뼈대 + 스킨 + `idle`·`walk`·`work`)를 읽어 방향 돌리기, 클립 고르기·대신하기, 뼈 자세가 바뀌는 것까지(`tests/c13_model_slots.gd`, ctest `engine_C13_model_slots`). 같은 검사가 저장소의 `character.glb`(디렉터 모델)도 읽어 봐요: 지금 파일의 클립은 `idle`·`walk`·`run`이고 `work`가 없어서 행동 키를 누르고 있을 때는 `idle`이 나와요.

## 3. 평면 그림 자리

| 파일 | 무엇 | 크기 |
| --- | --- | --- |
| `game/art/sprites/character_front.png` | 캐릭터 앞모습 (카메라 쪽을 볼 때) | 세로로 긴 그림 권장 약 256 × 400 px, **발바닥 = 그림 맨 아래 가운데**, 배경 투명 |
| `game/art/sprites/character_back.png` | 뒷모습 | 같은 크기 |
| `game/art/sprites/character_side.png` | 옆모습 (**오른쪽을 보는 그림**. 왼쪽은 코드가 뒤집어요) | 같은 크기 |
| `game/art/icons/tool_<id>.png` | 도구 줄 그림 11개 | **128 × 128 px**, 배경 투명 |

- 캐릭터 키는 `plant_art.character_height_m`(1.15 m)에 맞춰 늘려요. PNG를 넣으면 그 방향은 한 장 그림 + 코드 흔들림(걷기·달리기)으로 그려요. 넣지 않은 방향은 지금의 그려 둔 그림을 써요. `character.glb`가 있으면 평면 그림은 쓰지 않아요.
- 도구 `<id>`: `watering_can`(물뿌리개), `fertilizer`(비료), `compost`(퇴비), `lime`(석회), `hoe`(괭이), `mulch`(멀칭 필름), `disinfectant`(소독제), `inoculant`(유익균), `scissors`(가위), `pull`(뽑기), `predators`(천적 통).

## 4. 삼각형 예산 (권장)

| 무엇 | 권장 상한 | 근거 |
| --- | --- | --- |
| 포기 (`plant_stage4`) | **약 3,000** | 아래 측정: 3,168개에서 프레임 약 1.9 ms |
| 포기 단계 1~3, 시든 포기 | 단계 4보다 적게 | |
| 꽃·열매 덧붙임 | 각 **300 이하** | 포기 하나에 최대 꽃 4 + 열매 6개가 붙어요 (화면에 수천 개) |

**측정 (이 컴퓨터, 2026-11-20):** RTX 5070, Godot 4.7.2 Forward+, 1280 × 720, MSAA 4x, 해 그림자 켬(2단 분할), 수직 동기 끔. 작기 중간 장면(포기 640개: 단계 4가 608개, 꽃 약 2,460개, 열매 약 3,020개 덧붙임). 자리 채움 포기의 세밀함만 바꿔 3초씩 잰 평균이에요(프로토타입 `proto/m6b-check`의 `char_play.tscn -- p4=1 autoshot=<폴더>`가 출력. 본구현에는 이 측정 도구를 옮기지 않았어요).

| 단계 4 포기 삼각형 | 평균 프레임 | GPU 그리기 |
| --- | --- | --- |
| 576 | 1.43 ms | 1.17 ms |
| 3,168 | 1.93 ms | 1.65 ms |
| 8,928 | 2.88 ms | 2.61 ms |

- 고성능 그래픽 카드에서 잰 값이라 여유가 커 보여요. 노트북 내장 그래픽처럼 느린 기기는 몇 배 느릴 수 있어서, 권장 상한은 측정값보다 보수적으로 잡았어요(포기 3,000).
- 그림자를 끄거나 MSAA를 낮추면 더 빨라요. 실제 모델의 재질(텍스처 수, 투명도)에 따라 달라지니, 모델을 넣은 뒤 같은 명령으로 다시 재 보세요.
