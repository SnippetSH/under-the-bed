# 하드코어 2D 농사 시뮬레이션 게임 — 개발 계획서

Nov 13, 2026 · @RyuSeungHyun

## 1. 개요와 목표

### 콘셉트

비닐하우스 딸기 재배를 중심으로 토양 양분, pH·EC·CEC, 통기성, 미생물, 퇴비 분해 같은 현실 요소를 **단순화해서** 시뮬레이션하는 2D 탑다운 농사 게임이에요. 재미의 핵심은 "숨겨진 토양 상태를 측정하고 추론해서 처방하는 **진단 루프**"예요.

### 디자인 원칙

1. **모든 요소는 플레이어의 판단을 요구해야 존재할 수 있어요.** 새 판단을 만들지 못하는 요소는 다른 요소의 계수로 흡수시켜요.
2. **실패는 원인을 추적할 수 있어야 해요.** 작기가 끝나면 무엇이 언제 문제였는지 보여줘요.
3. **현실 정합성은 방향과 상호작용을 맞추는 수준까지만 챙겨요.** 절대 수치는 게임 밸런스가 우선이에요.
4. **정보에는 비용이 들어요.** 측정에는 돈, 시간, 장비가 필요해요.

### v1 범위

- 작물: 딸기 1종, 토경 재배
- 공간: 하우스 1동, 베드 단위 타일 그리드
- 기간: 1작기 (정식부터 수확 종료까지)

### 비목표 (v1에서는 하지 않아요)

- 3D, 멀티플레이
- 여러 작물 동시 지원
- 실제 영농 의사결정 도구 수준의 정량적 정확도
- 육묘 (별도 하우스의 모종 생산). 대신 모종 구매 시 품질 등급을 고르는 것으로 단순화해요 ([ADR-0006](decisions/0006-off-season-and-disinfection.md))

## 2. 운영 방식: 감독자와 AI 에이전트

### 역할

- **SeungH (디렉터·리뷰어)**: 명세 확정, 마일스톤 승인, 밸런스 판단, 우선순위 결정
- **AI 에이전트 (구현자)**: 코드 작성, 테스트 작성, 명세 문서 갱신, 시나리오 그래프 생성

### 저장소 문서 체계

- `AGENTS.md` (또는 `CLAUDE.md`): 에이전트 공통 규칙. 아래 "금지 사항"과 "리뷰 체크리스트"를 그대로 넣어요.
- `docs/plan.md`: 이 계획서를 마크다운으로 내보낸 것
- `docs/spec/`: 모듈별 상세 명세 (토양 수분, 질소, 양이온 교환, 딸기 생육 등). 에이전트가 구현 전에 먼저 작성하고, 감독자가 승인한 뒤에 코딩해요.
- `docs/decisions/`: 결정 기록(ADR). 무엇을 왜 단순화했는지 남겨요.
- `data/`: 모든 파라미터 파일
- `references/`: 공개 재배 자료, 토양 적정 범위 같은 참고 자료

### 작업 단위

- 이슈 1개 = 프로세스 1개 또는 기능 1개 = PR 1개
- 이슈마다 **목표, 입력 명세, 수용 기준, 금지 사항**을 적어요.
- 수용 기준은 "테스트 통과"와 "시나리오 그래프가 기대 방향을 보임" 두 가지로 구성해요.

### 에이전트에게 주는 지시 템플릿

- 목표: 무엇을 만드는지 한 문장
- 참조: 따라야 할 `docs/spec/` 문서
- 수용 기준: 통과해야 할 테스트와 시나리오
- 산출물: 코드, 테스트, 갱신된 명세, 그래프 이미지
- 금지: 명세 밖 기능 추가, 무관한 파일 수정

### 에이전트 금지 사항

- 명세에 없는 프로세스나 변수를 임의로 추가하지 않아요.
- 테스트를 통과시키려고 파라미터를 몰래 튜닝하지 않아요. 파라미터 변경은 별도 PR로 이유와 함께 올려요.
- 감독자 승인 없이 테스트의 기대값을 수정하지 않아요.
- 시뮬레이션 코어에 엔진, UI, 파일 입출력 코드를 넣지 않아요.

### 리뷰 체크리스트 (감독자용)

코드를 한 줄씩 읽기보다 아래 항목과 **그래프**를 확인하는 데 집중해요.

1. 코어가 엔진·OS와 무관한가
2. 같은 시드와 같은 입력이면 결과가 완전히 같은가 (결정론)
3. 상수가 코드에 하드코딩되지 않고 데이터 파일에서 오는가
4. 변수와 파라미터에 단위가 명시되어 있는가
5. 보존 법칙 테스트가 통과하는가 (예: 질소 총량 수지)
6. 시나리오 그래프가 기대한 방향으로 움직이는가
7. 명세 문서가 코드와 함께 갱신되었는가

## 3. 기술 스택과 아키텍처

### 구성 요소

| 구성 요소 | 역할 | 기술 |
| --- | --- | --- |
| sim-core | 시뮬레이션 전체. 순수 로직 | C++23 정적 라이브러리, CMake |
| sim-cli | 헤드리스 실행. 시나리오를 돌리고 CSV 출력 | C++ |
| tools | CSV를 그래프로 그리기, 파라미터 스윕 | Python |
| game | 렌더링, UI, 입력, 세이브 | Godot 4 + GDExtension 바인딩 |
| data | 작물, 토양, 비료, 미생물 파라미터 | JSON 또는 TOML |
| tests | 단위 테스트, 시나리오 회귀 테스트 | Catch2 또는 GoogleTest, CI |

### 핵심 원칙

- **코어와 엔진을 완전히 분리해요.** 엔진은 코어 상태를 읽어서 그리기만 하고, 플레이어 행동은 "명령"으로만 전달해요.
- **결정론**: 난수는 시드를 주입받아서만 써요. 같은 시드와 같은 명령 목록이면 결과가 비트 단위로 같아야 해요. 덕분에 리플레이와 회귀 테스트가 가능해요.
- **고정 타임스텝**: 1틱 = 게임 내 1시간. 게임 속도 배율은 엔진 쪽에서 프레임당 틱을 여러 번 호출하는 방식으로 처리해요.
- **데이터 주도**: 계수, 곡선, 작물 요구량은 전부 데이터 파일에 둬요. 작물 추가는 코드 수정이 아니라 데이터 추가여야 해요.

### 코어 공개 인터페이스 (자연어)

1. **초기화**: 파라미터 묶음과 시나리오(토양 초기 상태, 기상, 시작 날짜)를 받아 월드를 만들어요.
2. **명령 투입**: 플레이어 행동(관수, 시비, 환기 등)을 명령 큐에 넣어요. 명령은 다음 틱 시작 시 적용돼요.
3. **틱 진행**: N틱을 진행해요.
4. **상태 조회**: 읽기 전용 스냅샷을 돌려줘요. 진짜 값과 "플레이어가 측정한 값"을 구분해서 제공해요.
5. **이벤트 조회**: 이번 틱에 발생한 증상, 병 발생, 수확 가능 같은 이벤트 목록을 돌려줘요.
6. **직렬화**: 월드 전체를 저장하고 불러와요.

### 월드 데이터 구조

- 월드 → 하우스 (기온, 습도, CO2, 광량, 피복 겹수(기본 3중)·겹마다 양쪽 측창·난방 상태. [ADR-0011](decisions/0011-house-climate-in-m4.md))
- 하우스 → 베드 타일 그리드
- 타일 → 토양 셀 1개 + 작물 개체 0\~1개
- 토양 셀은 v1에서 단일층이고, 후반에 표층·근권 2층으로 확장할 수 있게 설계만 열어 둬요.

### Godot 쪽 책임

- 코어 스냅샷을 읽어 타일, 식물 스프라이트, 증상 표현을 결정
- 측정 오버레이, 그래프 패널, 영농일지 UI
- 입력을 명령으로 바꿔 코어에 전달
- 세이브 파일 관리 (내용 직렬화는 코어가 담당)

## 4. 토양 시뮬레이션 명세

모델은 **풀** (양이 쌓이는 곳)과 **플럭스** (풀 사이를 옮기는 속도)로 구성해요. 모든 속도는 "기본 속도 × 환경 계수들의 곱"이고, 환경 계수는 데이터 파일에 정의된 **구간 선형 곡선**으로 계산해요. 수치는 밸런싱으로 정하고, 명세는 **방향과 인과관계**만 고정해요.

### 상태 변수

| 변수 | 의미 | 플레이어가 알 수 있는 방법 | 도입 |
| --- | --- | --- | --- |
| 수분 | 토양 수분량. 포장용수량 기준 | 수분 센서 | M1 |
| 토양 온도 | 기온 추종 + 분해 발열 | 온도계 | M1 |
| 유기물 풀 | 퇴비의 탄소량, 질소량(C:N비), 분해 용이도 | 토양 검정 | M1 |
| 암모늄태 질소 (NH4+) | 분해 산물, 질산화 원료 | 토양 검정 | M1 |
| 아질산 (NO2-) | 질산화 중간체, 독성 | 토양 검정 | M1 |
| 질산태 질소 (NO3-) | 주 흡수 형태, 용탈되기 쉬움 | 토양 검정 | M1 |
| 통기성 지수 | 뛰리 호흡·미생물에 쓰이는 산소 가용도 | 간접 (증상) | M2 |
| 다짐 지수 | 통기성 상한을 결정, 경운으로 회복 | 간접 | M2 |
| pH | 양분 유효도와 미생물 활성에 영향 | pH 측정기 | M2 |
| 토양 용액 이온 | 녹아 있는 이온. 흡수 대상, EC 계산 원천 | 간접 | M2 |
| EC | 용액 이온 총량에서 유도 | EC 측정기 | M2 |
| CEC | 양이온 보유 능력. 토양 고유값 + 유기물 기여분 | 토양 검정 | M3 |
| 교환성 K, Ca, Mg, NH4 | CEC 자리에 붙어 있는 양 | 토양 검정 | M3 |
| 인산 | 총량과 pH에 따른 고정 | 토양 검정 | M3 |
| 미생물 개체군 | 분해균, 질산화균(1단계·2단계), 유익 길항균, 토양 병원균 | 고급 검정 | M5 |
| 망간 (교환성·용액·산화물) | 저pH·과습(환원)·토양 소독에서 산화물이 녹고 덜 붙어 과잉, 고pH에서 산화물로 굳어 결핍 | 토양 검정, 엽분석 | M3 ([ADR-0007](decisions/0007-acid-toxicity-and-manganese.md), [ADR-0010](decisions/0010-manganese-oxide-pool.md)) |
| 황, 붕소 등 미량원소 (망간 제외) | 단순 풀 | 토양 검정 | M8 |

### 프로세스 명세

1. **수분 수지**: 관수량을 더하고 증발산량을 빼요. 포장용수량을 넘는 분은 배수되고, 이때 용액 속 이온(특히 NO3-)이 배수량 비율만큼 함께 빠져나가요(용탈).
2. **토양 온도**: 하우스 기온 쪽으로 일정 지연을 두고 따라가고, 유기물 분해량에 비례한 발열을 더해요. 발열이 누적되면 뿌리 고온 장해가 생겨요.
3. **통기성**: 수분이 포장용수량 근처를 넘으면 떨어지고, 다짐 지수가 상한을 정해요. 유기물이 많으면 상한이 올라가요.
4. **유기물 분해**: 속도는 온도, 수분, 산소, 분해균 활성의 영향을 받아요. 분해되면 질소는 NH4+로 나오고 탄소는 날아가며 열을 내요. C:N비가 높으면 미생물이 토양 용액의 질소를 가져가서(부동화) 작물이 일시적으로 질소 부족을 겪어요. 미숙 퇴비는 분해가 빠르고 발열과 암모니아 발생이 커요.
5. **질산화 2단계**: 1단계(NH4+ → NO2-)와 2단계(NO2- → NO3-)의 속도를 따로 계산해요. 둘 다 온도와 산소의 영향을 받지만, **2단계는 고pH, 고암모니아, 저산소에서 더 크게 억제**돼요. 그 결과 NO2-가 쌓이고, 임계치를 넘으면 뿌리 독성 이벤트가 발생해요.
   - **아질산 독성의 pH 의존 (M2)**: 산성일수록 아질산(HNO2) 형태가 늘어 같은 농도라도 뿌리 독성이 커요. 독성 판정에 "pH → 독성 배율" 곡선을 곱해요(중성·알칼리 1).
   - **유리 암모니아의 온도 의존 (밸런싱)**: 온도가 오르면 같은 pH에서 NH3 비율이 늘어요(20 → 30 °C에서 약 2배). 유리 암모니아 지수에 온도 배율 곡선을 곱할지 밸런싱 단계에서 S2와 함께 정해요.
6. **탈질 (M4 이후 선택)**: 산소가 낮고 NO3-가 있으면 일부가 기체로 손실돼요.
7. **양이온 교환**: CEC 자리와 용액 사이의 분포가 평형 쪽으로 서서히 이동해요(완화 방식). 이온별 선택 계수로 우선순위를 정해요. 특정 이온을 과하게 넣으면 다른 이온이 용액으로 밀려나서 용탈 위험이 커지고, 흡수 단계에서도 길항 보정을 받아요.
8. **pH 변화**: 비료마다 산성화·알칼리화 계수를 두고, 질산화는 산을 만들어 pH를 낮춰요. 석회는 pH를 올려요. 변화폭은 완충력(CEC와 유기물에 비례)으로 나눠요.
   - **산성 장해**: 강산성에서 녹아 나오는 알루미늄의 뿌리 독성은 따로 계산하지 않고, "pH → 산성 장해 계수" 구간 선형 곡선으로 뿌리 건강도를 깎아요 (M2, [ADR-0007](decisions/0007-acid-toxicity-and-manganese.md)).
9. **유효도**: 각 양분의 유효량은 "용액 농도 × pH 유효도 곡선"이에요. 총량과 유효량을 분리하는 게 이 게임의 핵심이에요.
10. **EC**: 용액 이온 총량에 환산 계수를 곱해요.
11. **미생물 동역학 (M5)**: 각 개체군은 로지스틱 성장을 하고, 성장률은 환경 적합도(온도, 수분, pH, 먹이인 유기물)로 정해져요. 유익 길항균과 병원균은 서로 성장을 억제해요. 토양 소독은 **모든** 개체군을 줄여요. 태양열 소독(관수 → 멀칭 → 하우스 밀폐)은 토양 온도와 지속 시간에 따라 사멸량이 정해지고, 약제 소독은 약제별 계수로 정해요 ([ADR-0006](decisions/0006-off-season-and-disinfection.md)).

### 틱 처리 순서 (의사코드)

```
매 틱마다:
  명령 큐의 행동을 적용한다
  하우스 환경(기온, 습도, 광, CO2)을 갱신한다
  각 토양 셀에 대해:
    수분 → 온도 → 통기성 순서로 물리 상태를 갱신한다
    미생물 개체군을 갱신한다
    유기물 분해 → 질산화 → 양이온 교환 → pH 순서로 화학 상태를 갱신한다
    작물이 있으면 흡수량을 계산해 용액에서 뺀다
    배수에 따른 용탈을 처리한다
    EC, 유효도 같은 파생값을 다시 계산한다
  작물 생장과 생육 단계를 갱신한다
  증상·병 발생·독성 이벤트를 판정한다
  기록용 스냅샷을 남긴다
```

프로세스는 모두 "이번 틱의 변화량"을 계산하고, 어떤 풀도 음수가 되지 않도록 실제 이동량을 남은 양으로 제한해요.

## 5. 작물 모델 명세: 딸기

### 작물 상태

- 생육 단계와 단계 내 진행도
- 생체량 분배: 잎, 뿌리, 관부, 과실
- 뿌리 건강도 (0\~1): 과습, 고온, NO2- 독성, 병원균으로 감소
- 엽면적
- 원소별 체내 충족도 (0\~1)와 과잉 지수
- 스트레스 기록: 어떤 요인이 언제 얼마나 제한했는지 (작기 리포트용)
- 과실 목록: 개별 과실마다 착과 시점, 크기, 당도, 결함 플래그

### 생육 단계

정식·활착 → 영양생장 → 화아분화 → 개화 → 착과·비대 → 수확. 화방이 여러 번 반복돼요.

- 단계 전이는 적산온도, 일장, 온도 조건, 질소 상태로 판단해요.
- 질소가 과하면 화아분화가 늦어지는 경향을 넣어서, "비료를 많이 주면 좋다"는 직관을 깨는 장치로 써요.
- 단계별 양분 요구량은 데이터 테이블로 정의해요.

### 흡수

흡수량은 아래 요소들을 차례로 반영해서 계산하고, 토양 용액에서 실제로 빼요.

1. 단계별 요구량
2. 뿌리 건강도
3. 수분 계수 (건조하면 흡수 저하)
4. 염류 계수 (EC가 높으면 삼투 스트레스로 전체 흡수 저하)
5. 유효량 한도
6. 길항 보정 (K가 과하면 Ca·Mg 흡수 저하 등)

### 생장

- 광량, 기온, CO2로 잠재 생장량을 구하고, 스트레스 계수로 줄여요.
- **기본 모드**: 스트레스 중 가장 낮은 값 하나만 적용 (최소량의 법칙). 원인을 찾기 쉬워요.
- **하드 모드**: 스트레스를 전부 곱해요. 여러 요인이 겹치면 진단이 어려워져요.
- 두 방식 모두 코어에 구현하고 난이도 설정으로 고르게 해요.

### 증상 매핑 (게임용 단순화)

| 원인 | 화면에 보이는 증상 | 품질 영향 |
| --- | --- | --- |
| 질소 부족 | 아래 잎부터 황화, 생장 둔화 | 수량 감소 |
| 질소 과잉 | 잎만 무성, 진한 녹색 | 당도 저하, 병 취약, 화아분화 지연 |
| 칼륨 부족 | 잎 가장자리 갈변 | 당도·착색 저하 |
| 칼슘 부족 | 새 잎 끝이 마름 (팁번) | 과실 무름, 저장성 저하 |
| 마그네슘 부족 | 엽맥 사이 황화 | 수량 감소 |
| 붕소 부족 | 생장점 이상 | 기형과 증가 |
| EC 과다 | 잎끝 마름, 한낮 시듦 | 수량 감소 |
| NO2- 독성·토양 고온 | 급성 시듦, 뿌리 갈변 | 포기 고사 가능 |
| 암모니아가스 (알칼리 토양 + 암모늄 비료·미숙 퇴비, 밀폐) | 잎 가장자리 갈변, 수침상 반점 | 잎 손상, 심하면 고사 |
| 아질산가스 (강산성 토양 + 아질산 축적, 밀폐) | 잎에 흰 반점 | 잎 손상 |
| 과습·저산소 | 시듦, 생장 정체 | 뿌리 건강도 저하 |

증상은 원인과 1만 1로 대응하지 않도록 **겹치게** 설계해요. 예를 들어 "잎끝 마름"은 EC 과다일 수도, 칼슘 부족일 수도 있어서 측정이 필요해져요.

### 품질 지표

수확량, 당도, 크기, 기형과율, 저장성을 따로 계산해요. 판매 등급과 가격은 이 지표들로 정해져요.

## 6. 게임 디자인

### 코어 루프

관찰 → 측정 (비용 지불) → 가설 → 처방 → 결과 대기 → 피드백 → 다시 관찰

처방의 효과는 즉시 나타나지 않고 며칠에 걸쳐 나타나요. 이 시간 지연이 하드코어 난이도의 핵심이에요.

### 정보 계층

| 단계 | 수단 | 얻는 정보 | 비용 |
| --- | --- | --- | --- |
| L0 | 육안 관찰 | 잎·과실 증상, 생장 속도 | 없음 |
| L1 | 휴대 장비 | 수분, 온도, pH, EC (즉시) | 장비 구매 |
| L2 | 토양 검정 의뢰 | 질소 형태, 양이온, 인산, CEC, 유기물 | 비용 + 며칠 지연 |
| L3 | 엽분석, 미생물 검정 | 체내 양분, 병원균 밀도 | 고가 + 지연 |

- 측정값에는 오차가 있고, 장비 등급이 올라갈수록 오차가 줄어요.
- 측정값은 측정한 시점의 값이고, 시간이 지나면 "오래된 정보"로 표시돼요.
- 측정하지 않은 타일은 오버레이에서 "미지"로 보여요.

### 플레이어 행동

- **물 관리**: 관수량과 시간 지정, 점적 호스 설치
- **시비**: 비료 종류별 투입 (요소, 질산칼슘, 황산칼륨, 고토비료, 붕사, 복합비료 등. 전부 데이터로 정의), 엽면시비
- **토양 관리**: 퇴비 투입 (숙성도 선택), 석회, 경운과 베드 조성, 멀칭, 토양 소독, 유익균 투입, 토양 구매·교체 (같은 상품도 봉투마다 조성이 달라요, M8, [ADR-0009](decisions/0009-no-fixed-recipe-variation.md))
- **환경 관리**: 측창 개폐(겹마다 양쪽), 난방, 보온 커튼, 피복 겹수 변경(휴작기, 추가금) ([ADR-0011](decisions/0011-house-climate-in-m4.md))
- **작물 관리**: 적엽, 적과, 병든 포기 제거, 수확
- **정보**: 측정, 검정 의뢰, 장비 구매

### 경제

- 자금으로 자재·장비·검정·난방비를 지출해요.
- 판매가는 품질 등급과 시기별 시세로 정해져요. 시세가 높은 시기에 출하하려면 난방비를 더 써야 하는 식의 트레이드오프를 넣어요.

### 게임 모드

- **시나리오 모드**: 문제가 있는 토양을 주고 해결하는 퍼즐형. 튜토리얼 역할도 격해요.
- **커리어 모드**: 작기를 반복해요. 토양 상태가 다음 작기로 이월돼서 염류 집적, 연작 장해 같은 장기 문제가 생겨요. 작기 종료부터 다음 정식까지는 **하계 휴작기 정비** 구간이에요(소독, 경운, 퇴비, 베드 조성). 고온기 소독 직후 정식하면 질산화균이 회복되지 않아 암모늄·아질산이 쌓이는 함정이 생겨요.

### 난이도 레버

- 스트레스 결합 방식 (최소값 또는 곱셈)
- 측정 오차 크기
- 증상 표현의 명확도
- 토양 CEC (낮을수록 실수에 민감)
- 변동 크기 `variation_scale` (토양 상품 로트 편차, 행동 보정. [ADR-0009](decisions/0009-no-fixed-recipe-variation.md))

### 피드백 장치

- **작기 종료 리포트**: 주요 스트레스 원인을 타임라인으로 보여줘요. 실패 원인을 추적하는 장치예요.
- **영농일지**: 플레이어 행동과 측정값을 자동으로 기록해요.
- **그래프 패널**: 측정한 값의 추이만 보여줘요. 진짜 값은 리포트에서만 공개해요.

## 8. 검증과 밸런싱

### 단위 테스트

- **보존 법칙**: 질소 총량 = 초기량 + 투입량 − 흡수량 − 용탈량 − 기체 손실량. 양이온도 같은 방식으로 검사해요.
- **음수 금지**: 어떤 풀도 음수가 되지 않아요.
- **극한 입력**: 비료 100배, 관수 0, 기온 극단값에서도 발산하거나 NaN이 나오지 않아요.
- **결정론**: 같은 시드로 두 번 돌린 결과가 완전히 같아요.
- **견고성 (ADR-0009 도입 후)**: 표준 변동으로 시드 N개를 돌려도 시나리오 방향이 유지돼요. 기존 방향 테스트는 `variation_scale = 0`으로 메커니즘을 검증해요.
- **반(反)레시피 지표 (밸런싱)**: 한 시드에서 최적인 고정 처방을 다른 시드에 적용한 점수보다, 측정 기반 처방 점수가 꾸준히 높아야 해요.

### 시나리오 테스트 (방향 검증)

정확한 수치가 아니라 **방향과 순서**를 검증해요. 그래서 파라미터를 바꿔도 깨지지 않고, 인과관계가 깨질 때만 실패해요.

| ID | 조건 | 기대 결과 |
| --- | --- | --- |
| S1 | 미숙 퇴비 대량 투입 | 며칠 안에 토양 온도와 NH4+가 급증하고, 숙성 퇴비보다 크다 |
| S2 | 알칼리 토양 + 암모늄 비료 | 중성 토양보다 NO2- 최대치가 크다 |
| S3 | 과관수 | 적정 관수보다 NO3- 감소가 빠르다 |
| S4 | pH를 적정 범위 밖으로 | 총량이 충분해도 해당 원소 충족도가 낮다 |
| S5 | 칼륨 과다 시비 | Ca 흡수가 줄고 팁번 증상이 발생한다 |
| S6 | 저CEC 사토와 고CEC 양토에 같은 처방 | 사토 쪽의 양분·pH 변동폭이 더 크다 |
| S7 | 무처리 대조구 | 양분이 서서히 고갈되고 생장이 둔화된다 |

새 프로세스를 추가할 때는 그 프로세스의 인과관계를 보여주는 시나리오를 **함께** 추가해요.

### 스냅샷 회귀 테스트

- 고정 시드로 돌린 결과를 저장해 두고, 코드가 바뀜 때마다 비교해요.
- 의도한 변경으로 결과가 달라지면, 감독자 승인 후에만 스냅샷을 갱신해요.

### 밸런싱 절차

1. 에이전트가 파라미터 스윕을 돌리고 그래프를 만들어요.
2. 감독자가 그래프를 보고 값을 고르거나 방향을 지시해요.
3. 파라미터 파일을 갱신하고 변경 로그에 이유를 남겨요.

### 현실 정합성 참고

농촌진흥청 농사로 같은 공개 재배 자료에서 딸기 재배 기준과 토양 적정 범위를 모아 `references/`에 두고, 에이전트가 파라미터 초기값을 잡을 때 참조하게 해요. 출처가 없는 수치는 "게임용 임의값"으로 표시해요.

## 9. 리스크와 미결정 사항

### 리스크

| 리스크 | 대응 |
| --- | --- |
| 범위 폭발 | 마일스톤 승인 절차, "이 요소가 새 판단을 요구하는가" 점검 |
| 계수 상호작용으로 밸런싱 불가 | 요소를 하나씩 도입, 시나리오 테스트로 인과관계 고정 |
| 에이전트가 테스트를 맞추려고 계수를 조작 | 금지 사항 명시, 파라미터 변경은 별도 PR |
| 에이전트가 설계를 흐트러뜨림 | 구현 전 명세 문서 승인, ADR 기록 |
| 진단이 너무 어려워 재미가 없음 | 증상 명확도·측정 오차 조절, 작기 리포트 |
| 성능 (타일 수 × 틱 수) | C++ 코어, 목표: 헤드리스 1작기를 수 초 안에 실행 |

### 미결정 사항

- ~~**엔진 최종 선택** (Godot과 Unity 중)~~ → Godot 4로 결정 ([ADR-0001](decisions/0001-game-engine.md), 2026-11-18)
- **타일 해상도**: 포기 단위와 베드 구간 단위 중 선택
- **토양 층 수**: v1은 단일층, 2층 확장 시점
- **틱 길이**: 1시간 고정 유지 여부
- **재배 방식**: 실제 딸기 하우스는 고설 양액재배도 많아요. v1은 토경으로 하고, 고설 모드를 별도 콘텐츠로 넣을지 결정
- **아트 스타일과 증상 표현 방식**: 스프라이트 변형으로 보여줄지, 아이콘으로 보여줄지
