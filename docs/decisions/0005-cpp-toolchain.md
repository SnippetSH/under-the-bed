# ADR-0005: C++ 표준과 툴체인

- 상태: 승인 (2026-11-18)
- 날짜: 2026-11-18

## 맥락

계획서는 코어를 C++23으로 정했어요. 컴파일러마다 C++23 지원 범위가 달라서, 실제로 쓸 기능과 툴체인을 정해 둬야 나중에 컴파일러를 추가하거나 GDExtension을 붙일 때 문제가 적어요.

개발 환경(2026-11-18 확인): Windows 11, Visual Studio 2022 Community 17.14, CMake 4.4, Python 3.14.

## 결정

### 툴체인

- **컴파일러**: MSVC 19.38 이상(툴셋 v143, 14.38), x64
  - 2026-11-18 정정: 처음에는 IDE 버전(17.14)을 적었는데, 실제로 빌드에 쓰이는 컴파일러는 19.38이에요. 위 기능은 모두 19.38에서 빌드되는 것을 확인했어요.
- **빌드**: CMake 3.28 이상, `CMakePresets.json`으로 debug·release 프리셋을 정의해요. 생성기는 Visual Studio 2022예요.
- **CI**: GitHub Actions `windows-latest`에서 같은 프리셋으로 빌드하고 `ctest`를 돌려요.
- **Python 도구**: 3.12 이상, `tools/requirements.txt`로 의존성을 고정하고(`matplotlib` 등) 가상환경을 써요.

### C++ 표준

- `CMAKE_CXX_STANDARD 23`, `CMAKE_CXX_STANDARD_REQUIRED ON`, 컴파일러 확장은 꺼요.
- **적극적으로 쓰는 기능**: `std::expected`(코어의 오류 반환), `std::span`, `std::format`, `constexpr`, ranges 알고리즘
- **쓰지 않는 기능**: C++20 모듈(CMake·MSVC·godot-cpp 조합의 도구 지원이 아직 불안정해요), 코루틴
- `std::print`는 CLI와 도구에서만 써요. 코어는 입출력을 하지 않아요.

### 오류 처리

- 코어 공개 API는 예외를 밖으로 던지지 않아요. 실패할 수 있는 호출(초기화, 역직렬화, 잘못된 명령)은 `std::expected<T, Error>`를 돌려줘요.
- 내부 불변 조건 위반(음수 풀 등)은 디버그 빌드에서 assert로 잡고, 테스트로 막아요.

### 경고

- `/W4 /permissive- /utf-8`를 쓰고, CI에서는 `/WX`로 경고를 오류로 처리해요.
- 소스 파일은 UTF-8로 저장해요. (`/utf-8`은 한국어 주석 때문에 필요해요.)

## 근거

- MSVC 17.14는 위에 나열한 C++23 기능을 지원하고, 이미 설치되어 있어요.
- `std::expected`는 GDExtension 경계에서 예외가 엔진으로 새어 나가는 문제를 막아요.

## 결과

- 좋은 점: 설치된 도구만으로 바로 시작할 수 있어요.
- 감수하는 점: 처음에는 단일 컴파일러만 검증해요. 나중에 Clang(`clang-cl`)을 CI에 추가하면 이식성 문제를 더 일찍 잡을 수 있어요. 이건 M0 이후 선택 사항이에요.

## 검토한 대안

- **C++20으로 낮추기**: 이식성은 조금 좋아지지만 `std::expected`를 직접 구현해야 해요. 계획서의 C++23을 유지해요.
- **Ninja 생성기**: 빌드는 빠르지만 별도 설치나 개발자 프롬프트가 필요해요. 빌드 시간이 문제가 되면 프리셋을 추가해요.
