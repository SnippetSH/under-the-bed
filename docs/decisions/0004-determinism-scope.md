# ADR-0004: 결정론 보장 범위와 규칙

- 상태: 승인 (2026-11-18)
- 날짜: 2026-11-18

## 맥락

계획서는 "같은 시드와 같은 명령 목록이면 결과가 비트 단위로 같아야" 한다고 해요. 리플레이, 회귀 테스트, M6의 "CLI 결과와 동일" 기준이 모두 여기에 기대고 있어요. 하지만 부동소수점 결과를 컴파일러와 OS 사이에서까지 비트 단위로 맞추는 건 비용이 매우 커요. 그래서 보장 범위를 명시하고, 그 범위를 지키는 규칙을 정해요.

## 결정

### 보장 범위

- **보장**: 같은 바이너리(같은 컴파일러, 같은 빌드 옵션, 같은 플랫폼)에서 같은 파라미터, 같은 시드, 같은 명령 목록이면 **모든 틱의 상태가 비트 단위로 같아요.**
- **보장 안 함 (v1 비목표)**: 다른 컴파일러, 다른 OS, 다른 CPU 아키텍처 사이의 비트 단위 일치.
- 회귀 스냅샷의 기준 플랫폼은 Windows x64 + MSVC예요. 플랫폼을 추가하면 플랫폼별 스냅샷을 따로 두거나, 그 플랫폼에서는 허용 오차 비교를 해요.

### 규칙

1. **난수**
   - 코어 자체 PRNG(PCG32)와 자체 분포 함수(균등, 정규 등)만 써요. `std::*_distribution`은 표준 라이브러리 구현마다 결과가 달라서 금지예요. `rand()`와 `std::random_device`도 금지예요.
   - 마스터 시드에서 **서브시스템별 독립 스트림**(기상, 병 발생, 측정 오차 등)을 파생해요. 한 시스템에 난수 호출을 추가해도 다른 시스템의 난수열이 밀리지 않아서 회귀 스냅샷이 덜 깨져요.
   - **측정 오차 난수는 시뮬레이션 상태에 영향을 주지 않아요.** 플레이어가 측정을 하든 안 하든 진짜 토양 상태는 똑같이 진행돼야 해요.
2. **부동소수점**
   - 모든 물리량은 `double`이에요.
   - MSVC는 `/fp:precise`를 명시하고 FMA 축약을 끄며, Clang/GCC는 `-ffp-contract=off`를 써요. `/fp:fast`와 `-ffast-math`는 금지예요.
3. **하나의 코어 바이너리**: `sim-core`는 CMake 타깃 하나로 한 번만 빌드하고, CLI, 테스트, GDExtension이 모두 그것을 링크해요. GDExtension도 CMake로 빌드해서 컴파일 옵션이 갈라지지 않게 해요.
4. **순서 고정**
   - 타일은 행 우선 순서로 순회해요.
   - 결과가 `unordered_map`/`unordered_set`의 순회 순서에 의존하면 안 돼요.
   - 명령은 일련번호를 붙여 투입 순서대로, 다음 틱 시작 시 적용해요.
5. **외부 상태 금지**: 코어 안에서 실제 시계, 환경 변수, 파일, 스레드 스케줄링 결과를 쓰지 않아요. v1의 틱 처리는 단일 스레드예요.
6. **직렬화 왕복**: 저장에는 PRNG 상태를 포함해요. "N틱 실행 → 저장 → 불러오기 → M틱 실행"한 결과는 "N+M틱 연속 실행"과 비트 단위로 같아야 해요.
7. **검증 수단**: 직렬화한 상태 바이트의 해시(FNV-1a 64비트)를 틱마다 비교하는 `[determinism]` 테스트를 둬요.

## 근거

- 같은 바이너리 안에서의 결정론은 위 규칙만으로 지킬 수 있고, 리플레이·회귀 테스트·CLI와 게임 간 일치라는 실제 요구를 모두 만족해요.
- 크로스 플랫폼 비트 일치에는 고정소수점이나 자체 수학 함수가 필요한데, v1의 비목표(멀티플레이 없음)에 비해 비용이 너무 커요.

## 결과

- 좋은 점: 회귀가 깨지면 "코드가 바뀌었다"는 확실한 신호가 돼요. 버그 리포트를 시드와 명령 목록만으로 재현할 수 있어요.
- 감수하는 점: 컴파일러를 업그레이드하면 스냅샷이 바뀔 수 있어요. 그때는 디렉터 승인을 받아 스냅샷을 갱신하는 별도 PR을 올려요.

## 검토한 대안

- **고정소수점 연산**: 크로스 플랫폼 일치는 되지만, 지수·로지스틱 곡선 계산이 번거롭고 오버플로 관리 비용이 커요.
- **허용 오차 비교만 사용**: 구현은 쉽지만 리플레이가 보장되지 않고, 작은 비결정 버그를 놓쳐요.
