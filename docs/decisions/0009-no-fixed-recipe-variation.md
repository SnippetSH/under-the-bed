# ADR-0009: "항상 같은 정답"을 막는 변동 설계

- 상태: 승인 (2026-11-18)
- 날짜: 2026-11-18

## 맥락

코어는 결정론이에요(ADR-0004). 시작 조건(흙, 날씨, 시드)이 늘 같으면 최적 처방도 하나로 정해지고, 플레이어는 "이 날 이 비료 몇 g" 같은 **고정 레시피**를 외우게 돼요. 이건 계획서의 핵심 재미인 진단 루프(측정 → 추론 → 처방)를 무너뜨려요.

디렉터의 요구는 두 가지예요.

1. **항상 동일한 정답은 존재하지 않는다.** 정답에 가까운 판단은 있어도, 그게 매번 통한다는 보장은 없어야 해요.
2. **근사로 사라진 현실의 실패 요인을 되살린다.** 모델은 현실의 근사라서, 현실에서라면 실패로 이어졌을 작은 요인들이 빠져 있어요. 그 몫을 플레이어 행동에 붙는 작은 무작위 보정으로 대신해요.

동시에 지켜야 할 것이 있어요. 결정론(같은 시드 → 같은 결과), 실패의 원인 추적(디자인 원칙 2번), 보존 법칙, 그리고 시나리오 방향 테스트예요.

## 결정

변동을 세 층으로 나눠요. 모든 난수는 **주입받은 시드에서 나온 코어 자체 PRNG**만 써요(ADR-0004).

### 1층: 세계 변동 (판마다 다른 숨은 상태)

- **밭 생성**: 판(시나리오 인스턴스)마다 CEC, 초기 pH, 양분, 유기물, 다짐, (M5 이후) 미생물 밀도를 데이터에 정한 범위에서 생성해요. 베드마다 조금씩 다른 공간 불균일도 넣어요.
- **해마다 다른 날씨**: 고정 합성 1년 대신 시드로 그해 날씨를 생성해요(장마 길이, 이상고온·저온 주간, 흐린 날 수).
- **흙의 성격**: 인산 고정 속도, 양이온 세기 같은 숨은 계수를 밭마다 좁은 범위에서 흔들어요. 단, 측정·관찰로 알아낼 수 있는 범위로만 흔들어요.

### 2층: 토양 상품 변동 (봉투마다 다른 흙)

향후 **토양을 사서 교체하는 시스템**을 전제로 해요.

- 상품 정의(브랜드, 상품명)는 데이터에 **평균 조성 + 변동 폭**으로 둬요. 기초 화학(pH, 염류, 질소 형태, K·Ca·Mg, 인산, 유기물, CEC)과 (M5 이후) 미생물 조성이 대상이에요.
- 같은 상품이라도 **봉투(로트)마다** 시드로 실제 조성을 뽑아요. 봉투의 실제 값은 숨겨져 있고, 측정해야 알아요.
- 그래서 "이 브랜드면 된다"가 아니라 "이번 봉투는 측정해 보니 염류가 높다"가 돼요.

### 3층: 행동 보정 (원인 없는 작은 결과)

플레이어가 토양을 조절하려고 한 행동(관수, 시비, 퇴비, 석회, 토양 투입 등)에 작은 무작위 보정을 붙여요.

- **투입량 편차**: 실제 들어간 양 = 지정한 양 × (1 + ε). ε은 데이터에 정한 폭 안의 **유계 분포**(예: 삼각 분포 ±폭)에서 타일마다 따로 뽑아요. 뿌린 양이 베드마다 조금씩 고르지 않은 것과 같아요.
- **배경 투입**: 아무것도 안 해도 아주 작은 양이 생겨요. 예를 들어 하루 확률 p로 임의 원소가 임의 타일에 소량 들어오거나 빠져요. 현실의 관수 용수 불순물, 이웃 밭 비산, 모델에 없는 과정의 대리예요.
- 크기는 **미약하지만 시뮬레이션에 실제로 영향이 가는** 수준이에요. 처방을 뒤집지는 않지만, 같은 처방이 매번 같은 결과를 내지는 않아요.

### 공통 규칙

1. **결정론**: 용도별로 PRNG 스트림을 나눠요(세계 생성, 상품 로트, 행동 보정, 배경 투입). 한 용도에서 뽑는 횟수가 바뀌어도 다른 용도의 수열이 밀리지 않아요. 타일 순회는 행 우선이에요.
2. **원인 추적**:
   - 플레이 중에는 실제 값을 숨겨요.
   - 작기 리포트(M7)에서는 "지정한 양 대 실제 들어간 양", "배경 변동", "봉투 실제 조성"을 공개해요.
   - 무작위로 실패해도 "운"이라고 이름 붙은 항목으로 보여요.
3. **보존**:
   - 장부는 **실제 이동량**을 기록해요.
   - 배경 투입·유출은 별도 장부 항(예: `*_background_in_g`, `*_background_out_g`)에 둬서 보존식이 그대로 닫혀요.
4. **데이터 주도**: 모든 폭·확률·범위는 `data/`에 두고, 출처가 없으면 "게임용 임의값"으로 표시해요.
5. **난이도 레버**: 시나리오의 `variation_scale`(0 = 끔, 1 = 표준)로 2·3층의 크기를 조절해요. 계획서 6장 난이도 레버에 추가해요.
6. **테스트**:
   - 기존 시나리오 방향 테스트는 `variation_scale = 0`으로 메커니즘을 검증해요.
   - 변동 도입 시 **견고성 테스트**를 추가해요. 표준 변동으로 시드 N개를 돌려도 방향이 유지돼야 해요.
   - 밸런싱 지표로 **반(反)레시피 지표**를 둬요. 한 시드에서 최적인 고정 처방을 다른 시드들에 적용한 점수와, 측정 기반 처방 점수를 비교해요. 측정 기반 쪽이 꾸준히 이겨야 해요.

## 근거

- 세계 변동(1·2층)은 정답을 "레시피"에서 "절차"로 바꿔요. 실패 원인이 숨은 상태라서 측정했다면 알 수 있었고, 원칙 2번과 맞아요.
- 행동 보정(3층)은 근사의 부작용(현실보다 지나치게 정확한 세계)을 줄여요. 크기를 작게 두고 리포트에서 공개하면, 원인 추적을 해치지 않으면서 "보장된 정답"을 없애요.
- 시드 기반이라 리플레이와 회귀 테스트가 그대로 유지돼요.

## 결과

- 좋은 점: 매 판 측정이 필요해지고, 정보 비용(디자인 원칙 4번)이 의미를 가져요. 토양 상품 구매에도 "측정하고 쓸지" 판단이 생겨요.
- 감수하는 점: 밸런싱 대상이 늘어요(범위·폭·확률). 같은 시드여도 행동 순서가 다르면 3층 난수 소비가 달라져 결과가 달라져요. 이건 의도된 동작이에요.
- 계획서 갱신이 필요해요:
  - 6장 플레이어 행동에 "토양 구매·교체"를 추가해요.
  - 6장 난이도 레버에 `variation_scale`을 추가해요.
  - 7장 마일스톤에 각 층의 도입 시점을 넣어요.
  - 8장 검증에 견고성 테스트와 반레시피 지표를 추가해요.

## 검토한 대안

- **결과 주사위만**: 정답에 가까운 레시피가 여전히 존재하고, 실패 원인을 추적할 수 없어요.
- **세계 변동만(행동 보정 없음)**: 원인 추적은 가장 깔끔하지만, 측정을 충분히 하면 다시 "보장된 정답"이 생겨요. 디렉터 요구 2번을 채우지 못해요.
- **행동 보정을 비유계 정규분포로**: 드물게 극단값이 나와 처방을 뒤집을 수 있어요. 유계 분포로 상한을 둬요.
