# ADR-0003: 테스트 프레임워크로 Catch2 v3 채택

- 상태: 승인 (2026-11-18)
- 날짜: 2026-11-18

## 맥락

계획서는 단위 테스트(보존 법칙, 음수 금지, 극한 입력, 결정론), 시나리오 방향 테스트(S1~S7), 스냅샷 회귀 테스트를 요구하고, 프레임워크는 "Catch2 또는 GoogleTest"로 남겨 두었어요.

## 결정

- **Catch2 v3**를 CMake `FetchContent`로 가져오고, 버전 태그를 고정해요.
- 테스트는 CTest에 등록해서 `ctest`로 한 번에 돌려요.
- 테스트 종류는 태그로 구분해요.

| 태그 | 내용 | 실행 시점 |
| --- | --- | --- |
| `[unit]` | 개별 프로세스, 곡선 보간, 로더 검증 | 매 빌드 |
| `[conservation]` | 질소·양이온 총량 수지, 음수 금지 | 매 빌드 |
| `[extreme]` | 극한 입력에서 NaN·발산 없음 | 매 빌드 |
| `[determinism]` | 같은 시드 두 번 실행, 저장→불러오기 후 이어 돌리기 | 매 빌드 |
| `[scenario]` | S1~S7 방향·순서 검증 | 매 빌드 (느려지면 CI 전용) |
| `[regression]` | 고정 시드 스냅샷 비교 | CI |

- 시나리오 테스트는 CLI를 거치지 않고 코어 라이브러리를 직접 호출해요. 그래프는 별도로 CLI CSV와 Python 도구(`tools/`)로 만들어요.
- 회귀 스냅샷은 `tests/snapshots/`에 두고, 디렉터 승인 없이는 갱신하지 않아요.

## 근거

- `SECTION`과 `GENERATE`로 같은 초기 조건에서 갈라지는 시나리오(예: 미숙 퇴비 대 숙성 퇴비)를 읽기 쉽게 쓸 수 있어요.
- `Approx`와 matcher로 "방향과 순서" 검증을 간결하게 표현할 수 있어요.
- `FetchContent`로 외부 설치 없이 Windows에서 바로 빌드돼요.

## 결과

- 좋은 점: 디렉터가 테스트 이름과 태그만 보고 무엇이 검증되는지 파악할 수 있어요.
- 감수하는 점: GoogleTest보다 컴파일이 조금 느릴 수 있어요. 테스트 실행 파일을 태그 그룹별로 나눠서 대응해요.

## 검토한 대안

- **GoogleTest**: 성숙하고 기능도 충분해요. 다만 파라미터화 테스트 문법이 장황하고, 이 프로젝트에 특별히 필요한 기능 차이는 없어요.
- **doctest**: 가볍고 빠르지만 matcher 같은 기능이 Catch2보다 적어요.
