# ADR-0002: 파라미터 데이터 포맷으로 TOML 채택

- 상태: 승인 (2026-11-18)
- 날짜: 2026-11-18

## 맥락

계획서는 모든 계수, 곡선, 작물 요구량을 데이터 파일에 두고 포맷은 "JSON 또는 TOML"로 남겨 두었어요. 리뷰 체크리스트는 단위 명시와 출처 표시("게임용 임의값")를 요구해요. 또 코어에는 파일 입출력을 넣지 않는다는 원칙이 있어요.

## 결정

1. **파라미터 파일은 TOML**로 써요. 위치는 `data/`예요.
2. **시계열 입력(기상 데이터 등)은 CSV**로 써요. 시간당 한 행인 표 데이터는 TOML보다 CSV가 읽고 만들기 쉬워요.
3. **파싱은 코어 밖에서** 해요. 별도 로더 라이브러리 `sim-data`가 [toml++](https://github.com/marzer/tomlplusplus)(헤더 전용)로 파일을 읽고, 검증된 파라미터 구조체를 만들어 `sim-core`에 넘겨요. `sim-core`는 toml++에 의존하지 않아요.
4. **엄격한 로딩**:
   - 모르는 키가 있으면 오류예요. 오타 때문에 값이 조용히 무시되는 걸 막아요.
   - 필요한 키가 없으면 오류예요. 코드에 기본값을 두지 않아요. 코드 속 기본값은 하드코딩된 상수와 같기 때문이에요.
   - 범위 검사(음수 금지, 0~1 지수 등)는 로더에서 해요.
5. **표기 규칙**:
   - 키 이름에 단위를 붙여요. 예: `field_capacity_mm`, `base_rate_per_hour`
   - 구간 선형 곡선은 `[[x, y], ...]` 배열로 쓰고, x는 엄격하게 오름차순이에요.
   - 값마다 출처를 주석으로 달고, 출처가 없으면 `# 게임용 임의값`이라고 적어요.
6. Python 도구는 표준 라이브러리 `tomllib`으로 읽어요. 파라미터 스윕처럼 파일을 써야 하면 원본을 고치지 않고 오버라이드 파일을 생성해요.

## 근거

- TOML은 **주석**을 쓸 수 있어요. 출처와 "게임용 임의값" 표시를 값 바로 옆에 둘 수 있어요. JSON은 주석이 없어요.
- 사람이 직접 고치는 설정 파일에 적합하고, 문법이 단순해서 해석이 모호하지 않아요.

## 결과

- 좋은 점: 밸런싱 PR에서 값과 이유를 한눈에 볼 수 있어요. 오타나 누락된 키는 로딩 단계에서 바로 드러나요.
- 감수하는 점: 깊게 중첩된 구조는 TOML로 쓰기 불편해요. 작물·비료 정의처럼 같은 형태가 반복되면 `[[fertilizer]]` 같은 테이블 배열로 평평하게 유지해요.

## 검토한 대안

- **JSON**: 도구 지원은 가장 넓지만 주석이 없어서 출처 표기 규칙을 지키기 어려워요.
- **YAML**: 주석은 되지만 암묵적 타입 변환 같은 함정이 많고, C++ 파서가 무거워요.
