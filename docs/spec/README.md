# 모듈 명세

구현 전에 에이전트가 명세를 작성하고, 디렉터가 승인한 뒤에 코딩해요.
파일 이름은 모듈 단위로 짓고(예: `soil-water.md`, `nitrogen.md`), 상태는 문서 맨 위에 적어요.

## 상태 값

- **초안**: 작성 중. 코딩 금지
- **검토 요청**: 디렉터 검토 대기
- **승인**: 구현 가능. 이후 변경은 코드와 같은 PR에서 갱신
- **대체됨**: 다른 명세로 교체됨 (링크 표기)

## 템플릿

```markdown
# <모듈 이름>

- 상태: 초안
- 마일스톤: M?
- 관련 ADR: 

## 목적
이 모듈이 플레이어에게 어떤 판단을 요구하는지 한두 문장.

## 상태 변수
| 이름 (코드) | 의미 | 단위 | 범위 | 플레이어 관측 수단 |

## 파라미터 (data/ 위치)
| 키 | 의미 | 단위 | 초기값 | 출처 또는 "게임용 임의값" |

## 프로세스
각 플럭스를 "기본 속도 × 환경 계수들의 곱"으로 적고, 방향과 인과관계만 고정해요.
절대 수치는 밸런싱으로 정해요.

## 틱 처리 순서 내 위치

## 보존·불변 조건
예: 질소 총량 수지, 음수 금지.

## 시나리오 테스트
| ID | 조건 | 기대 방향 |

## 단순화와 비목표
```
