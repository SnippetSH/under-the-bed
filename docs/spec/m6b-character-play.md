# M6b: 캐릭터 플레이 (비스듬한 2.5D 화면, 걸어가서 하는 작업, 하루 단위 시간)

- 상태: **초안 (승인 대기)**. 승인 뒤 프로토타입(10장) → 최종 명세 승인 → 본구현
- 날짜: 2026-11-20
- 마일스톤: M6b ([ADR-0016](../decisions/0016-m6-split-and-character-play.md), 제안됨)
- 앞선 것: [m6-overview](m6-overview.md)(M6a: 바인딩 `SimWorld`, 세이브, 명령 기록, 점검 화면)
- 완료 기준: **캐릭터로 1작기를 플레이할 수 있고, 그 판의 명령 기록을 CLI로 돌리면 같은 결과가 나와요.**

M6a는 코어를 화면에 붙였어요. M6b는 그 위에 **플레이어가 캐릭터를 움직여 포기 앞까지 걸어가서 손으로 일하는 화면**을 만들어요. 시뮬레이션은 바꾸지 않아요. 새 프로세스·새 상태·새 파라미터·새 명령이 없어요. 캐릭터가 하는 일은 전부 M6a의 명령 17종 가운데 하나로 바뀌어 코어에 들어가요.

## 1. 범위

### 1.1 하는 것

| 항목 | 내용 | 장 |
| --- | --- | --- |
| 화면 | 비스듬히 내려다보는 하우스 안, 캐릭터를 따라가는 카메라 | 2 |
| 하우스 배치 | 베드·통로·장치·출입구의 자리 | 3 |

| 작업 | 도구를 들고 앞 칸에 행동, 장치 앞에서 조작 | 5 |
| 행동 표시 | 명령이 코어에 반영되기 전의 "했다" 표시 | 6 |
| 시간 | 하루 단위: 느린 진행, 자러 가기, 며칠 맡기기 | 7 |

## 2. 화면

- 시점: 비스듬히 내려다봐요. 바닥은 눕고, 포기·캐릭터·장치는 **서 있는 평면 그림**이에요. 앞에 있는 것이 뒤에 있는 것을 가려요.
- 참고 화면(디렉터 제시)에서 가져오는 것은 **시점과 화면 구성**(비스듬한 바닥, 서 있는 평면 그림, 위쪽 날짜·시각, 아래쪽 도구 줄)뿐이에요. 그림·캐릭터·UI 모양은 가져오지 않아요.
- 카메라는 캐릭터를 따라가요. 하우스 전체(4 × 20칸)가 한 화면에 다 들어오지 않아도 돼요.
- 만드는 방법은 둘이고, 프로토타입 P4에서 같은 장면을 둘 다 만들어 캡처로 비교해요(질문 A1).

| 방법 | 내용 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| 가. 2D | Godot 2D, 비스듬하게 그린 그림을 세로 위치 순서로 겹쳐 그려요 | 단순해요. M6a 점검 화면 코드와 같은 계열이에요 | 멀수록 작아지는 원근이 없어요. 참고 화면과 느낌이 달라요 |
| 나. 3D 공간 + 평면 그림 | 바닥은 평면, 포기·캐릭터는 세운 평면 그림, 원근 카메라 | 참고 화면과 같은 깊이감이 나요. 가림 순서를 엔진이 처리해요 | 장면·카메라·조명 설정이 늘어요. 그림 크기 맞추기가 번거로워요 |

- 그리는 상태는 m6-overview 5.2와 같아요(빈 칸, 포기 크기 단계, 꽃, 과실, 익어 가는 과실, 죽은 포기, 멀칭). 달라지는 것은 **한 칸에 포기 8개를 따로 그리는 것**이에요(상태는 같으니 같은 그림 8개. 자리만 조금씩 달라요). m6-overview 결정 D7(대표 포기 하나)은 점검 화면에만 남아요.
- 낮·밤 밝기는 꾸밈이에요. 진짜 값을 드러내지 않아요.
- HUD: 날짜·시각, 지금 든 도구와 양, 누적 수확, 대기 중인 행동 수. 숫자로 된 진짜 값은 개발자 패널(F3)에만 있어요(m6-overview 결정 D1 그대로).

## 3. 하우스 배치

코어의 그리드는 `bed_rows × bed_cols`(기준 4 × 20)이고 칸 하나가 1 m²예요. 배치는 **그림과 걷는 길만 정해요.** 결과에 들어가지 않아요.

- 베드 2개: 그리드의 0·1행이 왼쪽 베드, 2·3행이 오른쪽 베드예요. 베드 하나는 폭 2칸, 길이 20칸이에요.
- 통로 3개: 왼쪽 벽 쪽, 가운데, 오른쪽 벽 쪽. 모든 칸이 통로 하나와 맞닿아요.
- 장치 자리: 왼쪽·오른쪽 벽에 측창 손잡이(겹마다), 출입구 쪽에 난방기·유동팬 스위치·점적 밸브·자동 물 주기 조절기·작업대(정식, 피복 겹수), 침대 대신 **출입문**(자러 가기, 며칠 맡기기).
- 그리드 크기가 다른 시나리오는 "행을 2개씩 묶어 베드 하나"로 같은 규칙을 써요. 행 수가 홀수면 마지막 베드는 폭 1칸이에요.
- 칸·통로·캐릭터의 화면 크기는 게임 쪽 설정 파일 값이에요("게임용 임의값").

**확인하지 못한 것**: 코어의 측창 "좌·우"가 그리드의 어느 쪽인지(0행 쪽이 좌인지) 정해 둔 곳을 찾지 못했어요. 코어가 칸 위치와 창 방향을 연결해 쓰지 않는다면 화면에서 0행 쪽을 "좌"로 정하면 돼요. 프로토타입 전에 확인해요.

## 4. 캐릭터

- 이동: 방향키 또는 WASD, 8방향. 통로만 걸을 수 있어요. 베드와 벽은 막혀요.
- 바라보는 방향: 마지막으로 움직인 방향이에요.
- **대상 칸**: 캐릭터가 서 있는 통로 칸과 맞닿은 베드 칸 가운데 바라보는 쪽의 칸 하나예요. 화면에 테두리로 보여 줘요. 맞닿은 칸이 없으면 대상이 없어요.
- 걷는 속도는 게임 쪽 설정 파일 값이에요("게임용 임의값". 프로토타입에서 걸어 보고 정해요).
- 캐릭터 위치·방향은 **게임 쪽 상태**예요. 코어에 들어가지 않고 상태 해시에도 들어가지 않아요.

## 5. 작업

### 5.1 도구로 하는 칸 작업

- 화면 아래 도구 줄에서 도구를 골라요(숫자 키). 도구마다 종류와 양을 정해 둘 수 있어요(도구를 든 채 설정 키 → 작은 창).
- 행동 키(스페이스 또는 E)를 누르면 **대상 칸 1칸**에 그 도구의 명령을 넣어요(`TileArea` 1 × 1).
- 행동 키를 누른 채 걸으면 지나가는 대상 칸마다 한 번씩 넣어요. 같은 칸에 같은 틱 안에서 두 번 넣지 않아요(다시 넣으려면 키를 뗐다 눌러요).
- 넓은 범위를 한 번에 하는 도구는 M6b에 없어요(질문 A3).

| 도구 | 명령 | 도구 설정 |
| --- | --- | --- |
| 물뿌리개 | `irrigate` | mm |
| 퇴비 | `add_compost` | 종류, kg/m² |
| 비료 | `add_fertilizer` | 종류, g/m² |
| 석회 | `add_lime` | 종류, g/m² |
| 괭이(경운) | `till` | - |
| 멀칭 필름 | `set_mulch` | 종류(걷기 포함) |
| 소독제 | `apply_disinfectant` | 종류, g/m² |
| 유익균 | `add_inoculant` | 종류, g/m² |
| 가위(적화·적과) | `thin_flowers` | 포기당 남길 개수 |
| 뽑기 | `remove_plant` | - |
| 천적 통 | `release_predators` | 종류, 마리/m² |

### 5.2 장치 앞에서 하는 하우스 작업

장치와 맞닿은 통로 칸에서 그 장치를 바라보고 행동 키를 누르면 작은 조작 창이 열려요. 창이 열려 있는 동안 시간은 흘러요(일시정지는 7.4).

| 장치 | 명령 | 조작 |
| --- | --- | --- |
| 측창 손잡이 (겹·좌우마다) | `set_window` | 개방 단계 |
| 난방기 | `set_heater` | 켜기/끄기, 설정 온도 |
| 유동팬 스위치 | `set_fan` | 켜기/끄기 |
| 작업대: 피복 | `set_cover_layers` | 겹수 |
| 작업대: 점적 호스 | `install_drip` | 깔기 |
| 작업대: 모종 상자 | `plant` | 모종 등급, 포기/m². **하우스 전체를 한 번에 심어요**(코어의 정식 명령이 하우스 단위예요. 질문 A4) |
| 자동 물 주기 조절기 | (게임 쪽 설정, m6-overview 6.5) | 켜기/끄기, 시각, 양 |

- 거부된 명령은 화면 아래 알림으로 보여 줘요(m6-overview 6.1과 같아요).
- 자동 물 주기는 M6b에서도 기본 켜짐이에요(결정 D5). 80칸에 매일 손으로 물을 주면 그것만으로 하루가 가요.

## 6. 행동 표시 (코어 반영 전)

코어 규칙상 명령은 **다음 1시간이 시작될 때** 적용돼요. 7장의 느린 시간에서는 그 사이가 현실 시간으로 몇 분일 수 있어요. 그래서 화면은 둘을 갈라 보여 줘요.

- 행동 즉시: 대상 칸에 "방금 한 일" 표시(예: 물방울, 뿌린 가루)를 그려요. 이건 게임 쪽 표시이고 코어 상태가 아니에요.
- 다음 시간이 시작되면: 표시를 지우고 코어 상태대로 그려요. 거부됐으면 그때 알림이 떠요.
- 큐에 넣은 명령은 취소할 수 없어요(코어 규칙).

## 7. 시간

### 7.1 하루의 흐름

- 1틱 = 게임 1시간은 그대로예요. 달라지는 것은 **현실 시간으로 얼마나 빨리 틱을 부르느냐**뿐이라 결과에 들어가지 않아요.
- **일하는 속도**: 캐릭터를 움직일 수 있는 평소 상태예요. 게임 1시간 = 현실 N초이고, N은 게임 쪽 설정 파일 값이에요. 프로토타입 시작값은 **180초**(디렉터가 말한 3~4분의 아래쪽)로 두고, 걸어 본 뒤 정해요(질문 A2).
- **자러 가기**: 출입문에서 골라요. 다음 날 기상 시각(설정 파일 값, 시작값 6시)까지 빠르게 돌려요. 그동안 캐릭터는 움직이지 못해요.
- **며칠 맡기기**: 출입문에서 날 수를 정해요(1~30일). 그 날 수만큼 빠르게 돌린 뒤 기상 시각에 멈춰요. 장치 설정과 자동 물 주기는 그대로 돌아가요. 도중에 아무 키나 누르면 다음 기상 시각에 멈춰요.
- 빠르게 돌리는 속도는 m6-overview 3.4의 배속(하루 = 1초, 열흘 = 1초)을 써요.
- 밤에도 일할 수 있어요. 체력·피로가 없어서 자지 않아도 불이익이 없어요(M7에서 다뤄요).

### 7.2 한 작기에 걸리는 현실 시간 (계산)

- 일하는 속도 180초/시간이면 게임 하루를 깨어서 보내는 데 현실 72분이에요. 하루 4시간만 일하고 자면 12분이에요.
- 263일을 매일 4시간씩 일하면 약 53시간, 사흘에 한 번 4시간 일하고 나머지는 맡기면 약 18시간이에요.
- 그래서 **"며칠 맡기기"가 없으면 한 작기를 끝내기 어려워요.** 얼마나 자주 하우스에 들어가야 하는지는 밸런스 문제이고 M6b에서 정하지 않아요.

### 7.3 작기 끝

m6-overview 3.4와 같아요. 정한 틱 수(기준 263일)가 지나면 멈추고 종료 화면을 띄워요.

### 7.4 일시정지

- Esc로 메뉴를 열면 멈춰요. **멈춘 동안에는 캐릭터를 움직이거나 행동할 수 없어요.**
- m6-overview 결정 D2의 "일시정지 중 명령 + 영역 끌어 고르기"는 점검 화면에만 남아요.

## 8. 결정론과 저장

- 결과를 정하는 것은 여전히 "어느 틱 직전에 어떤 명령을 어떤 순서로 넣었는가"뿐이에요. 캐릭터 위치, 걷는 속도, 일하는 속도, 화면 방식은 들어가지 않아요.
- 명령 기록(m6-overview 7.4)은 그대로예요. 캐릭터 플레이 한 판의 기록을 CLI 일정표로 내보내 돌리면 같은 해시가 나와야 해요.
- 세이브 묶음의 게임 쪽 구역에 캐릭터 위치·방향, 든 도구, 도구별 설정, 자동 물 주기 설정을 더해요. 코어 세이브 형식은 그대로예요.
- 자러 가기·며칠 맡기기 도중에는 저장하지 않아요(멈춘 뒤에 저장해요).

## 9. 수용 기준

### 9.1 자동 검사 (M6a의 E0~E10은 그대로 통과해야 해요)

| ID | 무엇을 | 방법 | 기대 |
| --- | --- | --- | --- |
| C1 | 대상 칸 규칙 | 헤드리스에서 캐릭터를 정해 둔 통로 칸·방향에 놓고 대상 칸을 물어요(베드 양쪽, 끝, 맞닿은 칸 없음) | 4장 규칙과 같음 |
| C2 | 도구 → 명령 | 가짜 입력으로 걸어가 도구 11종을 각각 한 번 써요 | 명령 기록에 1 × 1 영역 명령이 도구마다 하나씩 |
| C3 | 누른 채 걷기 | 행동 키를 누른 채 통로 끝에서 끝까지 걸어요 | 지나간 칸마다 정확히 한 번, 빠진 칸·겹친 칸 없음 |
| C4 | 캐릭터 판 → CLI | C2·C3와 자러 가기·며칠 맡기기를 섞은 가짜 플레이를 돌리고 기록을 CLI로 다시 돌려요 | 모든 틱의 해시가 같음 |
| C5 | 속도와 무관 | C4를 일하는 속도 3가지(설정값, 10배, 100배)로 돌려요. 가짜 입력은 틱 기준으로 넣어요 | 최종 해시 같음 |
| C6 | 저장 왕복 | 캐릭터 판 도중 저장 → 불러오기 | 해시, 캐릭터 위치, 도구 설정이 같음 |
| C7 | 진짜 값 누출 없음 | m6-overview E8을 캐릭터 화면 폴더에도 적용 | 0건 |

### 9.2 화면에서 손으로 확인 (디렉터)

| # | 확인 | 통과 |
| --- | --- | --- |

## 11. 질문

### (a) 디렉터 판단이 필요한 것

| # | 질문 | 추천 |
| --- | --- | --- |
| A1 | 화면을 2D로 만들지, 3D 공간에 평면 그림을 세울지 | P4에서 둘 다 캡처해 보고 고르기. 참고 화면은 "나"에 가까워요 |
| A2 | 일하는 동안 게임 1시간 = 현실 몇 초인지 | 180초로 시작해서 P6에서 걸어 보고 정하기 |
| A3 | 넓은 범위 도구(한 줄 전체에 물 주기 등)를 M6b에 넣을지 | 넣지 않기. 한 칸씩 + 누른 채 걷기만. 넓은 도구는 M7에서 사는 장비로 |
| A4 | 정식을 걸어 다니며 칸마다 심게 할지 | M6b는 작업대에서 하우스 전체를 한 번에. 칸마다 심기는 코어의 정식 명령을 바꿔야 해요 |
| A5 | 수확을 캐릭터가 손으로 하게 할지 | M6b는 자동 수확 그대로. 손 수확은 코어 변경이라 포기 단위 판단(G7)과 함께 |
| A6 | 밤에 일하는 것을 막을지 | 막지 않기. 체력·피로는 M7 |

### (b) 따로 말이 없으면 구현자가 정하는 것

- 키 배치(이동, 행동, 도구 고르기, 설정 창), 대상 칸 테두리 모양, 행동 표시 그림
- 통로 폭, 장치의 정확한 자리, 카메라 높이·각도
- 하우스 배치 정보를 어느 파일에 둘지(게임 쪽 설정 파일)
- 헤드리스 검사에서 가짜 입력을 넣는 방법

## 12. 확인하지 못한 것

- 측창 좌·우와 그리드 방향의 관계(3장).
- "나" 방법에서 평면 그림 640개(포기) + 캐릭터를 그릴 때의 프레임 시간.
- 일하는 속도 180초에서 명령 반영까지 기다리는 느낌(6장)이 견딜 만한지.
- 포기 단위로 바꿀 때 틱 시간이 얼마나 느는지(ADR-0016).
