# 코어 API와 틱 루프 (M0)

- 상태: 승인 (2026-11-18)
- 마일스톤: M0
- 관련 ADR: [0002](../decisions/0002-data-format.md), [0004](../decisions/0004-determinism-scope.md), [0005](../decisions/0005-cpp-toolchain.md)

> M0 골격은 계획서 3장("코어 공개 인터페이스", "월드 데이터 구조")을 그대로 따르고, 이 문서는 그 세부 형태를 정해요.
> M0 승인(2026-11-18)과 함께 승인됐어요.

## 목적

플레이어 판단을 직접 만들지는 않아요. 이후 모든 프로세스(M1~)가 올라갈 틀을 만드는 문서예요. 결정론, 데이터 주도, 코어·엔진 분리를 처음부터 강제하는 게 목표예요.

## 구성 요소

| 타깃 | 역할 | 의존 |
| --- | --- | --- |
| `sim-core` | 월드 상태, 틱 루프, 명령 큐, 스냅샷, 이벤트, 직렬화, PRNG | 표준 라이브러리만 |
| `sim-data` | TOML·CSV 파일을 읽고 검증해서 `sim::Params`, `sim::Scenario`를 만듦 | `sim-core`, toml++ |
| `sim-cli` | 시나리오를 헤드리스로 실행하고 CSV 출력 | `sim-core`, `sim-data` |
| `tools/` | CSV 그래프, 합성 기상 데이터 생성 | Python |

## 공개 인터페이스 (`sim::World`)

| 계획서 항목 | 함수 | 설명 |
| --- | --- | --- |
| 1. 초기화 | `World::create(Params, Scenario)` | 검증 후 `std::expected<World, Error>` 반환 |
| 2. 명령 투입 | `enqueue(Command)` | 일련번호를 붙여 큐에 넣음. **다음 틱 시작 시** 투입 순서대로 적용 |
| 3. 틱 진행 | `step(ticks)` | N틱 진행 |
| 4. 상태 조회 | `snapshot()` | 읽기 전용 값 복사본 |
| 5. 이벤트 조회 | `events()` | **마지막 `step` 호출 동안** 발생한 이벤트. `step`을 부를 때마다 비워짐 |
| 6. 직렬화 | `serialize()` / `World::deserialize(bytes)` | 바이트 버퍼만 주고받음. 파일 쓰기는 호출자 몫 |
| (검증용) | `state_hash()` | 동적 상태의 FNV-1a 64비트 해시 |

- "진짜 값"과 "플레이어가 측정한 값"의 구분은 측정 기능이 생기는 M7에서 스냅샷에 추가해요. M0 스냅샷은 진짜 값만 있어요.
- 공개 API는 예외를 던지지 않아요.

## 시간과 달력

- 1틱 = 게임 내 1시간 (계획서 고정값. 데이터 파일 항목이 아니에요)
- **게임 달력은 윤년 없는 365일**이에요. 틱 0은 시나리오의 `start_day_of_year` 0시예요.
  - `day_of_year = (start_day_of_year - 1 + tick / 24) % 365 + 1`
  - `hour = tick % 24`
- 단순화 이유: 기상 입력을 연 단위로 반복해서 쓸 수 있고, 커리어 모드에서 작기를 이월할 때도 달력 계산이 단순해요.

## 상태 (M0)

| 이름 | 의미 | 단위 |
| --- | --- | --- |
| `tick` | 시작 이후 경과 틱 | h |
| `next_command_seq` | 다음 명령 일련번호 | - |
| `pending_commands` | 아직 적용되지 않은 명령 | - |
| 하우스 타일 그리드 | `bed_rows × bed_cols`. 타일 = 토양 셀 1개 + 작물 0~1개. M0에서는 필드가 비어 있음 | - |

정적 입력(직렬화에는 포함, 상태 해시에는 제외): 파라미터, 시나리오(시드, 시작일, 그리드 크기, 기상 표).

## 명령과 이벤트 (M0)

- 명령 종류는 `Noop` 하나뿐이에요. 명령 큐 구조와 적용 시점을 테스트하기 위한 것이에요. 실제 행동 명령은 해당 프로세스가 생기는 마일스톤에서 추가해요.
- 이벤트는 `CommandApplied` 하나예요(틱, 명령 일련번호). 영농일지의 "플레이어 행동 자동 기록"이 이 이벤트를 쓰게 돼요.

## 기상 입력

- 시나리오가 365일 × 24시간 = **8,760행**의 시간별 기상 표를 가져요. 행 수가 다르면 로딩 오류예요.
- 열: `day_of_year, hour, outside_air_temp_degC, solar_radiation_W_per_m2, outside_rh_percent`
- `#`으로 시작하는 줄은 주석이에요(출처 표기용). 첫 번째 주석 아닌 줄은 머리글이에요.
- M0 기본 데이터 `data/weather/synthetic_year.csv`는 `tools/gen_weather.py`가 만든 **게임용 임의값**이에요(중부 지방 기후를 흉내 낸 사인 곡선, 난수 없음).

## 데이터 파일 (M0)

- `data/params.toml`: `schema_version`만 있어요. M1부터 계수가 들어가요.
- `data/scenarios/empty.toml`: 빈 시나리오. 시드, 시작일, 그리드 크기, 기상 파일 경로(시나리오 파일 기준 상대 경로).

## 틱 처리 순서 (M0)

```
매 틱마다:
  명령 큐의 행동을 적용한다 (CommandApplied 이벤트 기록)
  tick += 1
```

이후 마일스톤에서 계획서 4장의 순서대로 프로세스가 끼워져요.

## 불변 조건과 테스트

| 태그 | 검증 내용 |
| --- | --- |
| `[unit]` | PCG32 기준 출력값 일치, 균등 분포 범위, 스트림 독립성, 달력 계산, 기상 조회, 명령 적용 시점, 이벤트 비움 |
| `[unit]` (로더) | 정상 로딩, 모르는 키·빠진 키·행 수 오류 거부 |
| `[determinism]` | 같은 입력 두 번 실행 시 매 틱 해시 일치(1년), 저장→불러오기→이어 실행 = 연속 실행, 직렬화 왕복 바이트 일치 |
| M0 완료 기준 | `data/scenarios/empty.toml`을 8,760틱 실행하고 결정론 테스트 통과 |

## 단순화와 비목표

- 윤년 없음, 서머타임 없음
- 크로스 플랫폼 비트 일치는 보장하지 않음 ([ADR-0004](../decisions/0004-determinism-scope.md))
- 세이브 파일 형식 버전 호환(이전 버전 세이브 불러오기)은 M6에서 다시 다뤄요. M0에서는 버전이 다르면 오류예요.
